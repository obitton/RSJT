## Overview

Add fixture-backed smoke coverage and local release documentation for the first usable version. This ticket does not add new runtime product behavior. It hardens the current workflow by proving the API route surface can walk through customer intake, match review, staged writeback, tech update extraction, expense entry, reminder checks, contact card preview, and payout-ready state without live external writes.

## API Smoke Test Flow

Add `apps/api/src/tests/end-to-end-smoke.integration.test.ts`.

Fixture services:

- `FixtureAuthService`
- `FixtureMessagingWebhookService`
- `FixtureMatchingService`
- `FixtureApprovalService`
- `FixtureWritebackExecutionService`
- `FixtureUpdateExtractionService`
- `FixtureJobMoneyService`
- `FixtureReminderService`
- `FixtureContactCardService`

The test should execute this flow through `app.inject`:

1. Receive a fixture Twilio inbound webhook at `POST /webhooks/twilio/messages`.
2. Search for RepairShopr matches with `POST /jobs/:jobId/matches/search`.
3. Select a fixture match with `POST /jobs/:jobId/matches/:candidateId/select`.
4. Create and approve a staged writeback approval with `/approvals`.
5. Execute the approved writeback with `/writebacks/approvals/:approvalId/execute`, using a fixture executor that returns a local success response only.
6. Extract a tech update with `POST /jobs/:jobId/updates/extract`.
7. Save money details with `PATCH /jobs/:jobId/money`.
8. Confirm the response is payout-ready.
9. Generate reminders with `POST /reminders/generate`.
10. Preview the contact card with `GET /manager/conversations/:conversationId/contact-card/preview`.

Assertions:

- Every route returns the expected status code.
- The fixture services record the expected calls in order.
- Payout-ready is true after the money update.
- Writeback execution never calls a live external writer.
- Twilio webhook handling returns empty TwiML and does not send outbound messages.
