# IP01.11 - Manager Dashboard - Implementation Plan

**Date:** 2026-05-26
**Story Points:** 5
**Project Plan:** PP01-service-referral-ops-agent
**Local Ticket:** RSJT-011
**Dependencies:** RSJT-006, RSJT-008, RSJT-009

## Overview

Build the manager dashboard read surface for local operational state. The manager role should be able to open the Expo app, see grouped job queues, see unresolved items separately from reconciled work, inspect active takeover conversations, and drill into a job detail screen without any external sends or RepairShopr writes.

This ticket also normalizes the upcoming dashboard wording to `manager`. New code, APIs, components, tests, and new docs should not use personal names or legacy role wording.

Fresh documentation check:

- Expo SDK reference was checked on 2026-05-26. The existing app already uses Expo 56 packages, and this ticket does not change SDK versions.
- Expo Router notation confirms route groups do not affect URLs. `src/app/(manager)/manager/index.tsx` maps to `/manager`.
- Expo Router navigation docs confirm links can target app URLs directly, including dynamic routes.
- TanStack Query remains the app's existing server-state pattern.

## Proposed Structure

- Add shared manager dashboard DTOs in `packages/shared/src/domain/dashboard.ts`.
- Add an API repository that aggregates existing `jobs`, `approvals`, `conversations`, `match_candidates`, `expenses`, and `payouts` data into read models.
- Add a `ManagerDashboardService` boundary so route tests can inject fixtures without database setup.
- Add authenticated manager-only API routes:
  - `GET /manager/dashboard`
  - `GET /manager/jobs/:jobId`
- Extend the mobile API client with dashboard methods.
- Replace the manager placeholder screen with a role-specific dashboard that uses segmented filters, compact summary panels, and job rows.
- Upgrade the shared job detail route to render manager job details when a manager opens it.

## API Shape

### `GET /manager/dashboard`

Requires a `manager` role session.

Response:

```json
{
  "summary": {
    "openCount": 2,
    "scheduledCount": 1,
    "completedCount": 0,
    "unmatchedCount": 1,
    "takeoverCount": 0,
    "payoutReadyCount": 1
  },
  "groups": {
    "openJobs": [],
    "scheduledJobs": [],
    "completedJobs": [],
    "unmatchedJobs": [],
    "payoutReadyJobs": []
  },
  "takeoverConversations": []
}
```

### `GET /manager/jobs/:jobId`

Requires a `manager` role session.

Returns one job detail read model with related pending approval counts, selected match reference, and payout fields when present.

## File-By-File Changes

### `packages/shared/src/domain/dashboard.ts`

Add manager dashboard schemas:

- `ManagerDashboardSummarySchema`
- `ManagerDashboardJobSchema`
- `TakeoverConversationSummarySchema`
- `ManagerDashboardResponseSchema`
- `ManagerJobDetailParamsSchema`
- `ManagerJobDetailResponseSchema`

Use existing shared schemas where possible:

- `JobStateSchema`
- `RepairShoprReferenceSchema`
- `SplitCategorySchema`
- `ProfitBasisSchema`
- `MoneyCentsSchema`
- `ApprovalRiskSchema`
- `MatchConfidenceBandSchema`

Dashboard job rows should include:

- `id`
- `state`
- `customerLabel`
- `updatedAt`
- optional `repairShoprReference`
- optional money fields
- `pendingApprovalCount`
- optional selected match confidence band

### `packages/shared/src/domain/domain.test.ts`

Add schema tests for:

- Valid manager dashboard response.
- Valid manager job detail response.
- Rejecting invalid job state and invalid UUIDs.

### `packages/shared/src/index.ts`

Export `./domain/dashboard.js`.

### `apps/api/src/repositories/manager-dashboard-repository.ts`

Add a repository with read-only methods:

- `getDashboard()`
- `getJobDetail(jobId)`

Rules:

- Open jobs: `intake`, `accepted`.
- Scheduled jobs: `scheduled`.
- Completed jobs: `completed`.
- Unmatched jobs: `unmatched`.
- Payout-ready jobs: `payout_ready`.
- Takeover conversations: `conversations.takeoverActive = true`.
- Unresolved groups must not include `completed`, `payout_ready`, or `closed`.
- Sort each group by `updatedAt` descending.
- Include RepairShopr references only when both entity type and ID are present.
- Parse all responses with shared Zod schemas before returning.

### `apps/api/src/services/manager-dashboard-service.ts`

Add:

- `ManagerDashboardStore`
- `ManagerDashboardServiceApi`
- `ManagerDashboardService`

The service should be thin and should not calculate business rules that belong in the repository query grouping.

### `apps/api/src/routes/manager-routes.ts`

Add manager-only routes:

- `GET /manager/dashboard`
- `GET /manager/jobs/:jobId`

Behavior:

- Use `app.requireRole(request, ["manager"])`.
- Return `503` if the dashboard service is unavailable.
- Return `404` when a job detail is missing.

### `apps/api/src/app.ts`

Wire the default manager dashboard service when `db` is available:

- Import `ManagerDashboardRepository`.
- Import `ManagerDashboardService`.
- Import `registerManagerRoutes`.
- Add optional `managerDashboardService` to `AppOptions`.
- Register manager routes after auth and before generic job/update routes.

### `apps/mobile/src/api/client.ts`

Add methods:

- `getManagerDashboard(token)`
- `getManagerJobDetail(token, jobId)`

Use existing request helpers and local runtime validators.

### `apps/mobile/src/dashboard/dashboard-validation.ts`

Add mobile runtime validators for the manager dashboard response and job detail response. Keep the same local validation style used by auth and job update feed validation.

### `apps/mobile/src/dashboard/dashboard-format.ts`

Add formatting helpers:

- Dashboard group labels.
- Money display from cents.
- Pending approval label.
- Empty state copy for each group.

### `apps/mobile/src/app/(manager)/manager/index.tsx`

Replace the placeholder dashboard with:

- Header showing signed-in manager.
- Summary counts.
- Segmented group filter.
- Job list with state, label, charge/profit, and pending approval count.
- Takeover conversation list.
- Empty, loading, and error states.
- Links to `/jobs/[jobId]` for job rows.
- Sign out action retained.

### `apps/mobile/src/app/(shared)/jobs/[jobId].tsx`

Upgrade the placeholder route:

- Read `jobId` from `useLocalSearchParams`.
- Use `getManagerJobDetail` for manager sessions.
- Show job state, RepairShopr reference, pending approvals, selected match, and money fields.
- Keep a simple fallback for non-manager roles until later tech detail work exists.

### `.project-management/2-project-plans/PP01-service-referral-ops-agent.md`

Keep the targeted RSJT-011 rename to `Manager Dashboard`.

### `.project-management/5-local-tickets/PP01-local-tickets.md`

Keep the targeted RSJT-011 rename to `Manager Dashboard`.
