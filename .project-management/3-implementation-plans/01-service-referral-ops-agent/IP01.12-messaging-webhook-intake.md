# IP01.12 - Messaging Webhook Intake - Implementation Plan

**Date:** 2026-05-26
**Story Points:** 8
**Project Plan:** PP01-service-referral-ops-agent
**Local Ticket:** RSJT-012
**Dependencies:** RSJT-003, RSJT-004

## Overview

Add the inbound messaging webhook boundary for Twilio SMS, MMS, and future WhatsApp sandbox traffic. This ticket validates Twilio signatures, parses form-encoded webhook payloads, persists inbound messages plus media metadata, records outbound status callback events, and returns an empty TwiML response. It must not send customer-facing messages.

Fresh documentation check:

- Twilio messaging webhook docs were checked on 2026-05-26. Incoming message webhooks and outbound status callbacks are the two relevant Programmable Messaging webhook types.
- Twilio webhook request docs confirm Twilio posts messaging webhooks as `application/x-www-form-urlencoded`.
- Twilio security docs recommend the Twilio SDK helper for signature validation and warn that webhook params can change over time.
- Status callback docs confirm status callback payloads vary by channel and include message status changes after initial message creation.

Sources:

- https://www.twilio.com/docs/usage/webhooks/messaging-webhooks
- https://www.twilio.com/docs/messaging/guides/webhook-request
- https://www.twilio.com/docs/usage/webhooks/webhooks-security
- https://www.twilio.com/docs/messaging/guides/outbound-message-status-in-status-callbacks

## Proposed Structure

- Add `@fastify/formbody` so Fastify can parse Twilio form posts.
- Add `twilio` as the API package SDK dependency for request signature validation.
- Add shared messaging schemas that parse known Twilio fields while allowing unknown future fields.
- Add a message media table and webhook event table in the local database.
- Extend the messages repository with inbound and status-event persistence methods.
- Add a `TwilioWebhookVerifier` wrapper around the Twilio SDK helper.
- Add a `MessagingWebhookService` that validates, persists, and returns no-reply TwiML.
- Add unauthenticated webhook routes that rely on Twilio signature validation instead of app session auth.

## API Shape

### `POST /webhooks/twilio/messages`

Receives Twilio inbound message webhooks.

Behavior:

- Requires a valid `X-Twilio-Signature`.
- Parses `application/x-www-form-urlencoded`.
- Upserts or finds a conversation by the external sender phone or channel address.
- Persists the inbound message.
- Persists zero or more media metadata rows based on `NumMedia`.
- Stores the raw form payload for audit/debugging.
- Returns empty TwiML with `Content-Type: text/xml`.

Response:

```xml
<Response></Response>
```

### `POST /webhooks/twilio/status`

Receives Twilio outbound status callbacks.

Behavior:

- Requires a valid `X-Twilio-Signature`.
- Parses `application/x-www-form-urlencoded`.
- Persists the status callback event keyed by `MessageSid`.
- Updates the local message status when a matching outbound message exists.
- Returns `204`.

## File-By-File Changes

### `apps/api/package.json`

Add dependencies:

- `@fastify/formbody`
- `twilio`

Do not add a custom cryptographic validation implementation.

### `packages/shared/src/domain/messaging.ts`

Add schemas and types:

- `TwilioInboundWebhookSchema`
- `TwilioStatusCallbackSchema`
- `MessageMediaSchema`
- `MessagingWebhookEventSchema`
- `InboundMessageRecordSchema`

Important shape rules:

- Use `z.object(...).passthrough()` for Twilio form payloads because Twilio can add params.
- Require `MessageSid`, `From`, `To`, `Body`, and `NumMedia` for inbound messages.
- Require `MessageSid` and `MessageStatus` for status callbacks.
- Treat all form values as strings at the schema boundary.
- Parse `NumMedia` with coercion and validate it is a non-negative integer.

### `packages/shared/src/domain/domain.test.ts`

Add schema tests for:

- SMS inbound payloads.
- MMS inbound payloads with `MediaUrl0` and `MediaContentType0`.
- WhatsApp-style sender values.
- Status callback payloads with extra unknown params.
- Invalid `NumMedia`.

### `packages/shared/src/index.ts`

Export `./domain/messaging.js`.

### `packages/db/src/schema.ts`

Update the DB schema:

- Add `messages.externalStatus` nullable text.
- Add a unique index on `messages.twilioMessageSid` for non-null Twilio SIDs if Drizzle supports the partial expression cleanly. If partial indexes are awkward in schema code, add the unique index in the SQL migration only and leave the regular schema index.
- Add `messageMedia` table:
  - `id`
  - `messageId`
  - `mediaIndex`
  - `contentType`
  - `url`
  - `createdAt`
- Add `messagingWebhookEvents` table:
  - `id`
  - `eventType` as text, values `inbound_message` or `status_callback`
  - `twilioMessageSid`
  - `payload`
  - `createdAt`

### `packages/db/src/migrations/0003_messaging_webhook_intake.sql`

Add the migration generated or hand-written from the schema update:

- Add `external_status` to `messages`.
- Add unique protection for non-null `twilio_message_sid`.
- Create `message_media`.
- Create `messaging_webhook_events`.
- Add indexes for message media and webhook event lookup.

### `apps/api/src/integrations/twilio/twilio-webhook-verifier.ts`

Add:

- `TwilioWebhookVerifier`
- `TwilioWebhookVerificationInput`

Rules:

- Use `twilio.validateRequest`.
- Build the validation URL from `APP_BASE_URL` plus `request.url` so tests and deployed webhook URLs use the same public URL.
- Validate with the complete parsed form payload.
- Return `false` when the signature header or auth token is missing.

### `apps/api/src/repositories/messages-repository.ts`

Keep existing `createJobUpdateMessage`.

Add methods:

- `findOrCreateConversationForExternalPhone(input)`
- `createInboundTwilioMessage(input)`
- `createMessageMedia(input)`
- `recordMessagingWebhookEvent(input)`
- `updateMessageExternalStatus(input)`

Repository rules:

- Use a transaction for inbound message, media, and webhook event persistence.
- Treat duplicate `MessageSid` as idempotent and return the existing message ID.
- Store inbound messages with `direction = "inbound"` and `authorRole = null`.
- Store media metadata only. Do not fetch media URLs in this ticket.

### `apps/api/src/services/messaging-webhook-service.ts`

Add:

- `MessagingWebhookStore`
- `MessagingWebhookVerifier`
- `MessagingWebhookServiceApi`
- `MessagingWebhookService`

Methods:

- `handleInboundMessage(requestContext, payload)`
- `handleStatusCallback(requestContext, payload)`

Behavior:

- Verify Twilio signature before persistence.
- Parse payloads with shared schemas.
- Persist inbound message, media metadata, and raw event payload.
- Persist status callbacks and update local message status when possible.
- Return empty TwiML for inbound messages.
- Never send an outbound message.

### `apps/api/src/routes/twilio-webhook-routes.ts`

Add routes:

- `POST /webhooks/twilio/messages`
- `POST /webhooks/twilio/status`

Route rules:

- Do not require app auth.
- Return `403` for invalid Twilio signatures.
- Return `415` if the request was not form-encoded and Fastify cannot parse it.
- Set `Content-Type: text/xml` for inbound TwiML.
- Return `204` for status callbacks.

### `apps/api/src/app.ts`

Wire webhook support:

- Register `@fastify/formbody`.
- Add optional `messagingWebhookService` to `AppOptions`.
- Build the default service when `db`, `TWILIO_AUTH_TOKEN`, and `APP_BASE_URL` are available.
- Register Twilio webhook routes before authenticated app routes.

### `.project-management/5-local-tickets/PP01-local-tickets.md`

Mark RSJT-012 done only after implementation and full verification pass.
