# IP01.17 - Expenses, Profit, And Split Review - Implementation Plan

**Date:** 2026-05-26
**Story Points:** 5
**Project Plan:** PP01-service-referral-ops-agent
**Local Ticket:** RSJT-017
**Dependencies:** RSJT-007, RSJT-008, RSJT-011

## Overview

Add local money review for completed jobs: tech-entered charge, expenses, and reported profit, calculated profit basis, split category handling, and payout readiness. Tech sessions can enter and edit closeout money details without manager approval. Manager sessions can review the same money summary and override the split category with an explicit audit reason.

The existing database already has `jobs`, `expenses`, `payouts`, and `audit_events` support for this ticket, so this plan does not add a migration unless implementation uncovers a missing column. Payout readiness is derived from job completion plus enough money detail:

- `reported_profit` when a reported profit is present.
- `charge_minus_reported_expenses` when no reported profit exists and gross charge exists.

Fresh documentation check:

- Expo Router was checked on 2026-05-26. The file-based route model supports adding tech and manager money review screens under the existing route groups.
- TanStack Query mutation docs were checked on 2026-05-26. The existing mobile mutation and query invalidation pattern is still appropriate for save and split override actions.
- React Native TextInput docs were checked on 2026-05-26. Numeric money fields can use platform keyboard hints while still validating cents conversion locally.

## Proposed Structure

- Add shared job money DTOs for expenses, summaries, update requests, split override requests, and responses.
- Add a DB-backed `JobMoneyRepository` that reads and writes `jobs`, `expenses`, and `audit_events`.
- Add a `JobMoneyService` that calculates profit basis, payout readiness, and manager/tech split shares from `SplitPercentByCategory`.
- Add authenticated API routes:
  - `GET /jobs/:jobId/money`
  - `PATCH /jobs/:jobId/money`
  - `POST /manager/jobs/:jobId/split-override`
- Add mobile validators, format helpers, and screens for tech closeout money entry and manager split review.
- Surface money review links from the tech job feed and manager job detail.

## Safety Rules

- No customer-facing communication is sent.
- No RepairShopr write endpoint is called.
- Tech-entered charge, expense, and profit values do not require manager approval.
- Manager split override requires a non-empty audit reason and records an `audit_events` entry.
- Payout readiness is local app state only. It does not trigger payout finalization or external transfer.

## API Shape

### `GET /jobs/:jobId/money`

Requires `tech` or `manager` role.

Returns the job money summary:

```json
{
  "summary": {
    "jobId": "uuid",
    "state": "completed",
    "isCompleted": true,
    "splitCategory": "new_lead",
    "grossChargeCents": 18000,
    "reportedExpenseCents": 2500,
    "reportedProfitCents": null,
    "calculatedProfitCents": 15500,
    "profitBasis": "charge_minus_reported_expenses",
    "managerPercent": 20,
    "techPercent": 80,
    "managerShareCents": 3100,
    "techShareCents": 12400,
    "payoutReady": true,
    "missingFields": []
  },
  "expenses": []
}
```

### `PATCH /jobs/:jobId/money`

Requires `tech` or `manager` role.

Updates money details and replaces the editable expense list for that job. Nullable money fields clear a previously entered value.

```json
{
  "grossChargeCents": 18000,
  "reportedProfitCents": null,
  "completed": true,
  "expenses": [
    {
      "category": "parts",
      "amountCents": 2500,
      "description": "Replacement adapter"
    }
  ]
}
```

The route recalculates:

- total reported expenses.
- profit basis.
- calculated profit.
- manager and tech split shares.
- payout readiness.
- job state transition to `payout_ready` only when completion and money details are sufficient.

### `POST /manager/jobs/:jobId/split-override`

Requires `manager` role.

```json
{
  "splitCategory": "customer_service_heavy",
  "reason": "Extra customer-service effort required."
}
```

The route updates the job split category, recalculates shares, and writes an audit event.

### `apps/api/src/repositories/job-money-repository.ts`

Add repository methods:

- `getMoney(jobId)`
- `replaceMoney(input)`
- `overrideSplitCategory(input)`

Implementation details:

- `getMoney` reads one job plus related expenses.
- `replaceMoney` updates job money columns and replaces expense rows in one transaction.
- `overrideSplitCategory` updates the job split category and inserts an audit event in one transaction.
- Repository output is parsed through shared schemas via the service layer.

### `apps/api/src/services/job-money-service.ts`

Add:

- `JobMoneyStore`
- `JobMoneyServiceApi`
- `JobMoneyService`
- `JobMoneyNotFoundError`
- `SplitOverridePermissionError`

Responsibilities:

- Calculate reported expense total.
- Prefer reported profit when present.
- Otherwise calculate profit from charge minus reported expenses.
- Clamp negative calculated profit to zero because shared money values are non-negative.
- Use `SplitPercentByCategory` for percentages.
- Compute shares with manager share rounded to cents and tech share as the remainder.
- Derive missing fields:
  - `completion`
  - `split_category`
  - `gross_charge`
  - `profit_detail`
- Mark a job `payout_ready` only when complete, split category exists, and a profit basis exists.

### `apps/api/src/routes/job-money-routes.ts`

Add routes:

- `GET /jobs/:jobId/money`
- `PATCH /jobs/:jobId/money`
- `POST /manager/jobs/:jobId/split-override`

Route behavior:

- `GET` and `PATCH` require `tech` or `manager`.
- Split override requires `manager`.
- Missing jobs return 404.
- Non-manager split override attempts return 403 through the auth plugin.
- Invalid request bodies return 400 through the app Zod handler.

## Tests

### Shared

- Valid money summary parses with charge-minus-expense basis.
- Valid money summary parses with reported-profit basis.
- Invalid negative money is rejected.
- Empty split override reason is rejected.
- Update request can clear reported profit.

### Repository

- Reads job money with expenses.
- Replaces job money and expense rows in one transaction.
- Writes split override audit event with reason.
- Returns null for missing jobs.

### Service

- Uses reported profit before calculated profit.
- Calculates profit from gross charge minus reported expenses when no reported profit exists.
- Calculates manager and tech shares from `SplitPercentByCategory`.
- Marks payout ready only when completed and money detail is sufficient.
- Keeps incomplete jobs out of payout-ready state.

### Routes

- Requires authentication.
- Allows tech to get and patch money details.
- Allows manager to get and patch money details.
- Requires manager role for split override.
- Returns 404 for missing jobs.
- Returns 400 for invalid money payloads.

### Mobile

- Validators reject malformed money responses.
- Format helpers parse dollars to cents and format split labels.
