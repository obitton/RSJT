## Overview

Build the first real mobile app shell: role-aware sign-in, persisted session token storage, typed API access, and manager/tech landing routes. This ticket turns the current Expo placeholder into a usable local app frame without building job-update or dashboard workflows yet.

Fresh documentation check:

- Expo latest SDK reference on 2026-05-22 lists SDK 56 as latest, with React Native 0.85, React 19.2.3, and minimum Node.js 22.13.x.
- Expo Router protected routes are the current auth routing pattern for SDK 53 and later.
- Expo SecureStore is included in Expo Go and is appropriate for local persisted session token storage.
- TanStack Query official docs confirm React Query works with React Native and is installed with `pnpm add @tanstack/react-query`.

Sources:

- https://docs.expo.dev/versions/latest/
- https://docs.expo.dev/router/advanced/protected/
- https://docs.expo.dev/router/advanced/authentication/
- https://docs.expo.dev/versions/latest/sdk/securestore/
- https://tanstack.com/query/latest/docs/framework/react/installation

## Proposed Structure

- Upgrade `apps/mobile` from SDK 55 to latest stable SDK 56 before adding new auth shell code.
- Add `expo-secure-store`, `@tanstack/react-query`, and a workspace dependency on `@rsjt/shared`.
- Use Expo Router protected routes with a root `Stack`.
- Add an auth provider that stores the API bearer token in SecureStore on native and local storage on web.
- Add a typed fetch client for the existing API auth routes.
- Use `@rsjt/shared` as a type-only dependency in mobile. Keep mobile runtime validation local until the shared package has a Metro-safe built output.
- Add manager and tech route groups with simple landing screens.
- Keep the UI quiet and operational: no marketing page, no decorative hero, no external sends.

## Route Structure

```text
apps/mobile/src/app/
|-- _layout.tsx
|-- index.tsx
|-- sign-in.tsx
|-- (manager)/
|   |-- _layout.tsx
|   `-- manager/
|       `-- index.tsx
|-- (tech)/
|   |-- _layout.tsx
|   `-- tech/
|       `-- index.tsx
`-- (shared)/
    |-- _layout.tsx
    `-- jobs/
        `-- [jobId].tsx
```

Behavior:

- `/sign-in` is available only while logged out.
- `/` becomes a role router after auth state loads.
- `/manager` routes live inside `(manager)` and require a manager session.
- `/tech` routes live inside `(tech)` and require a tech session.
- `/jobs/[jobId]` routes live inside `(shared)` and require any valid session.
- Do not put `index.tsx` directly under both role groups because Expo Router group indexes still map to `/`.

## File-By-File Changes

### `apps/mobile/package.json`

Update Expo SDK packages to latest stable SDK 56 using official Expo install tooling:

```bash
pnpm --filter @rsjt/mobile exec expo install expo@latest
pnpm --filter @rsjt/mobile exec expo install --fix
pnpm --filter @rsjt/mobile exec expo install expo-secure-store
pnpm --filter @rsjt/mobile add @tanstack/react-query @rsjt/shared@workspace:*
```

If Expo install rewrites SDK-compatible versions for existing packages, keep those changes.

### `apps/mobile/app.json`

Keep the existing Expo Router plugin and React Compiler setting. Add `expo-secure-store` to plugins only if Expo install or SecureStore docs require configuration for the current SDK. Do not enable `requireAuthentication` in V1 because the docs note biometric auth is not supported in Expo Go with that option.

### `apps/mobile/src/api/client.ts`

Add:

- `ApiError`
- `ApiClient`
- `createApiClient`
- `login`
- `getSession`
- `logout`

Use `fetch`, not axios. Use type-only DTO imports from `@rsjt/shared` for `LoginRequest`, `LoginResponse`, and `SessionUser`. Validate runtime responses with small local guards in `apps/mobile/src/auth/session-validation.ts` because Metro cannot bundle the current NodeNext shared source barrel that re-exports `.js` specifiers from TypeScript files.

API base URL:

- Read `process.env.EXPO_PUBLIC_API_BASE_URL`.
- Default to `http://127.0.0.1:47630` for simulator and web local testing.
- Keep this in `.env.example` so physical device testing can point at a LAN or tunnel URL.

### `apps/mobile/src/auth/session-validation.ts`

Add local runtime guards:

- `toLoginResponse`
- `toSessionUser`
- `isRecord`

These guards must mirror the shared auth DTO shape without importing the shared runtime barrel.

### `apps/mobile/src/auth/session-storage.ts`

Add storage helpers:

- `getStoredSession`
- `setStoredSession`
- `clearStoredSession`

Use `expo-secure-store` on native and local storage on web. Store a compact JSON object with token and user. Handle missing or malformed values by returning `null`, not by throwing during app boot. Keep the persisted payload compact so it stays comfortably below SecureStore platform limits.

### `apps/mobile/src/auth/auth-context.tsx`

Add:

- `AuthProvider`
- `useAuth`
- `signIn(username, passcode)`
- `signOut()`
- initial stored-session load
- session validation through `GET /auth/session` when a token exists

Rules:

- Failed session validation clears storage.
- Sign-in stores the returned token and user.
- Sign-out calls API logout when possible, clears local storage either way, and does not swallow UI state updates.

### `apps/mobile/src/app/_layout.tsx`

Wrap the app in:

- `QueryClientProvider`
- `AuthProvider`
- `RootNavigator`
- `StatusBar`

Use `Stack.Protected`:

- logged-out guard for `sign-in`
- logged-in guard for `index`
- manager guard for `(manager)`
- tech guard for `(tech)`
- logged-in guard for `(shared)`

While the auth provider is loading stored session state, expose only the `index` loading route. Do not make `sign-in` available until stored-session validation has completed.

### `apps/mobile/src/app/index.tsx`

Replace placeholder content with a small role-router screen:

- Show loading copy while auth state is loading.
- Redirect manager users to `/manager`.
- Redirect tech users to `/tech`.
- Redirect logged-out users to `/sign-in`.

### `apps/mobile/src/app/sign-in.tsx`

Add a simple operational login screen:

- username input
- passcode input with secure entry
- submit button
- error text for failed login
- disabled submit while login is pending

Use existing seeded local users:

- `manager`
- `tech`

Do not hardcode real person names.

### `apps/mobile/src/app/(manager)/manager/index.tsx`

Add a manager landing screen with:

- current user role/status
- links or static sections for approval inbox, matches, and dashboard placeholders
- logout action

### `apps/mobile/src/app/(tech)/tech/index.tsx`

Add a tech landing screen with:

- current user role/status
- static sections for update capture and assigned work placeholders
- logout action

### `apps/mobile/src/app/(shared)/jobs/[jobId].tsx`

Add a minimal job detail placeholder that reads `jobId` from route params and displays it. This keeps the shared route group real and typechecked for later tickets.

### `apps/mobile/src/components/*`

Add small reusable UI primitives:

- `Screen`
- `FormField`
- `ActionButton`

Keep them plain React Native, no external UI kit.

### `.env.example`

Add:

```text
EXPO_PUBLIC_API_BASE_URL=http://127.0.0.1:47630
```
