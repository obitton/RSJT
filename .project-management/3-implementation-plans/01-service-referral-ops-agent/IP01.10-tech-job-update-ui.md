# IP01.10 - Tech Job Update UI - Implementation Plan

**Date:** 2026-05-26
**Story Points:** 5
**Project Plan:** PP01-service-referral-ops-agent
**Local Ticket:** RSJT-010
**Dependencies:** RSJT-006, RSJT-007, RSJT-009

## Overview

Build the first functional tech job update workflow in the Expo app. The tech role should be able to load active and unresolved local jobs, select a job, submit a natural-language internal update, and review extracted facts plus missing-field prompts returned by the existing API extraction route.

This ticket also fixes the mobile API client boundary discovered before implementation: JSON requests with a body must send `Content-Type: application/json`, otherwise Fastify rejects them with `415 Unsupported Media Type`.

Fresh documentation check:

- Expo SDK reference on 2026-05-26 still lists SDK 56 as the latest stable SDK line.
- Expo Router route notation confirms route groups do not affect URLs and `(group)/index.tsx` maps to `/`.
- Expo Router protected routes remain the current client-side route-guard pattern.
- Expo typed routes are generated by Expo CLI when enabled in `app.json`.
- TanStack Query official guides confirm `useQuery` for server state and `useMutation` for writes.
- MDN fetch examples set `Content-Type: application/json` when sending a JSON request body.
- Fastify content type parser docs confirm `application/json` is natively supported and unsupported content types throw invalid media type errors.

## Proposed Structure

- Keep role naming generic: `manager` and `tech` only.
- Add a shared response DTO for the job update feed.
- Add an API job feed route that reads local job rows and returns active and unresolved jobs.
- Seed deterministic local demo jobs so the mobile app has data after `pnpm --filter @rsjt/db db:seed`.
- Extend the mobile API client with job feed and update extraction methods.
- Keep mobile runtime validation local, while importing shared DTOs as types only.
- Replace the tech landing placeholder with a real, mobile-first update capture workflow.
- Do not send SMS, email, RepairShopr writes, or any external communication.

### `packages/shared/src/domain/jobs.ts`

Add:

- `JobUpdateFeedResponseSchema`
- `JobUpdateFeedResponse`

Shape:

```ts
export const JobUpdateFeedResponseSchema = z.object({
  activeJobs: z.array(JobSummarySchema),
  unresolvedJobs: z.array(JobSummarySchema),
});
```

Use the existing `JobSummarySchema` so mobile and API keep one DTO contract.

### `packages/db/src/seed.ts`

Extend the local seed script:

- Keep seeded `manager` and `tech` users unchanged.
- Insert deterministic local jobs with fixed UUIDs and generic labels.
- Include at least one `accepted`, one `scheduled`, and one `unmatched` job.
- Use `onConflictDoNothing()` so seed stays repeatable.

### `apps/api/src/repositories/jobs-repository.ts`

Add a repository that reads job rows and maps them to `JobSummary`.

Methods:

- `listActiveForUpdates()`
- `listUnresolvedForUpdates()`

Rules:

- Active states: `accepted`, `scheduled`.
- Unresolved states: `unmatched`, `intake`.
- Sort newest first by `updatedAt`.
- Include RepairShopr reference only when both stored reference fields exist.
- Parse output through `JobSummarySchema`.

### `apps/api/src/services/job-update-feed-service.ts`

Add a small service boundary:

- `JobUpdateFeedStore`
- `JobUpdateFeedServiceApi`
- `JobUpdateFeedService`

The service returns `JobUpdateFeedResponseSchema.parse({ activeJobs, unresolvedJobs })`.

### `apps/api/src/routes/jobs-routes.ts`

Add:

- `GET /jobs/update-feed`

Behavior:

- Requires any authenticated user.
- Returns `503` if the feed service is unavailable.
- Returns active and unresolved job arrays.

### `apps/api/src/app.ts`

Register the new jobs route and default feed service:

- Import `JobsRepository`.
- Import `registerJobsRoutes`.
- Import `JobUpdateFeedService`.
- Add optional `jobUpdateFeedService` to `AppOptions`.
- Register before matching routes so job reads are available with the rest of the authenticated app.

### `apps/api/src/repositories/jobs-repository.test.ts`

Add database-backed tests:
