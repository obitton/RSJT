# IP01.5 - RepairShopr Read Client - Implementation Plan

**Date:** 2026-05-19
**Story Points:** 5
**Project Plan:** PP01-service-referral-ops-agent
**Local Ticket:** RSJT-005
**Dependencies:** RSJT-002, RSJT-004

## Overview

Create a read-only RepairShopr integration inside the API package. This ticket adds typed fetch helpers for the RepairShopr entities needed by matching and job context, while explicitly avoiding write methods, live API calls in tests, and mobile exposure of RepairShopr credentials.

Official sources checked on 2026-05-19:

- RepairShopr REST API help center: `https://repair.uservoice.com/knowledgebase/articles/376312-repairshopr-rest-api-build-custom-extensions-app`
- RepairShopr OpenAPI document: `https://api-docs.repairshopr.com/swagger.json`

Source-backed constraints:

- Base URL is `https://{subdomain}.repairshopr.com/api/v1`.
- API docs are OpenAPI/Swagger-backed.
- RepairShopr warns that non-GET calls can modify live site data.
- Rate limit is 180 requests per minute per IP address.
- This ticket must only implement GET methods and fixture-backed tests.

## Proposed Structure

- Keep RepairShopr integration server-only under `apps/api/src/integrations/repairshopr`.
- Use the shared `RepairShoprReferenceSchema` vocabulary for normalized external references.
- Keep raw RepairShopr DTOs narrow and permissive enough for fixture-backed reads, but validate fields needed by downstream matching.
- Use injected transport, clock, and sleep dependencies in tests so retries, timeouts, and throttling are deterministic.
- Do not add RepairShopr config to the mobile app or shared package.
- Do not require RepairShopr credentials for API health checks or auth. Missing credentials should fail only when constructing or using the RepairShopr client.

## File-By-File Change List

### `apps/api/src/config.ts`

**Change:** Add optional RepairShopr environment fields to the API config schema.

```ts
REPAIRSHOPR_SUBDOMAIN: z.string().min(1).optional(),
REPAIRSHOPR_API_KEY: z.string().min(1).optional(),
REPAIRSHOPR_TIMEOUT_MS: z.coerce.number().int().positive().default(10000)
```

**Why:** Keeps credentials server-only and available to the integration without making local health/auth development require live RepairShopr access.

### `apps/api/src/integrations/repairshopr/repairshopr-types.ts`

**Change:** Add Zod schemas and types for the read DTOs and query objects.

Include:

- `RepairShoprMetaSchema`
- `RepairShoprCustomerSchema`
- `RepairShoprContactSchema`
- `RepairShoprLeadSchema`
- `RepairShoprTicketSchema`
- `RepairShoprAppointmentSchema`
- `RepairShoprInvoiceSchema`
- `RepairShoprPaymentSchema`
- `RepairShoprTicketCommentSchema`
- List response schemas for each supported collection
- Query input schemas for read methods

Keep schemas focused on fields needed by matching:

- IDs
- names and labels
- phone, mobile, email, and address fields
- customer/contact/ticket references
- timestamps
- ticket status, subject, number, and problem type
- invoice/payment totals, paid state, and ticket/customer references
- ticket comment body, subject, visibility, and timestamps

**Why:** Gives the API typed read payloads without pretending to model every RepairShopr field in v1.

### `apps/api/src/integrations/repairshopr/repairshopr-rate-limiter.ts`

**Change:** Add a small deterministic rate limiter.

Behavior:

- Default limit: 180 requests per 60,000 ms.
- Accept injectable `now` and `sleep` functions for tests.
- Track request timestamps in memory.
- Remove timestamps outside the current window before deciding whether to wait.
- If the window is full, wait until the oldest timestamp exits the window.

**Why:** Matches RepairShopr's documented per-IP limit and lets tests assert behavior without sleeping for real time.

### `apps/api/src/integrations/repairshopr/repairshopr-client.ts`

**Change:** Add a read-only client class and helper factory.

Configuration:

```ts
type RepairShoprClientConfig = {
  subdomain: string;
  apiKey: string;
  timeoutMs: number;
};
```

Transport:

```ts
type RepairShoprTransport = (
  url: URL,
  init: { method: "GET"; signal: AbortSignal }
) => Promise<Response>;
```

Public methods:

- `listCustomers(query?: RepairShoprCustomerQuery)`
- `getCustomer(id: number)`
- `listContacts(query?: RepairShoprContactQuery)`
- `getContact(id: number)`
- `listLeads(query?: RepairShoprLeadQuery)`
- `getLead(id: number)`
- `listTickets(query?: RepairShoprTicketQuery)`
- `getTicket(id: number)`
- `listAppointments(query?: RepairShoprAppointmentQuery)`
- `getAppointment(id: number)`
- `listInvoices(query?: RepairShoprInvoiceQuery)`
- `getInvoice(id: number)`
- `listPayments(query?: RepairShoprPaymentQuery)`
- `getPayment(id: number)`
- `listTicketComments(query?: RepairShoprTicketCommentQuery)`
- `listTicketCommentsForTicket(ticketId: number, query?: RepairShoprTicketCommentForTicketQuery)`
- `toReference(entityType, record)`

Request behavior:

- Always use `GET`.
- Build URLs under `https://{subdomain}.repairshopr.com/api/v1`.
- Attach `api_key` as a query parameter at request time.
- Serialize arrays as repeated query parameters unless Swagger explicitly expects comma-separated input.
- Apply timeout with `AbortController`.
- Retry transient failures only:
  - HTTP `429`
  - HTTP `500`, `502`, `503`, `504`
  - network errors thrown by the transport
- Do not retry timeout aborts.
- Do not retry `400`, `401`, `403`, or `404`.
- Raise a typed `RepairShoprApiError` with status, endpoint, and response text for non-success responses.
- Never log API keys or complete URLs containing `api_key`.

**Why:** Keeps the first integration read-only, testable, rate-limited, and safe for later matching work.

### `apps/api/src/integrations/repairshopr/fixtures/*.json`

- customers
- contacts
- leads
- tickets
- appointments
- invoices
- payments
- ticket comments

Redact or invent all personal values. Fixtures must not contain live customer data or real credentials.

**Why:** Enables deterministic tests with no live RepairShopr calls.

### `apps/api/src/integrations/repairshopr/repairshopr-client.test.ts`

**Change:** Add unit tests for client behavior.

Cover:

- Builds base URL from subdomain and `/api/v1`.
- Adds `api_key` without exposing it in thrown messages.
- Supports each read-only collection and by-ID method.
- Asserts every transport invocation uses `GET`.
- Parses fixture responses into typed DTOs.
- Normalizes each supported entity to `RepairShoprReference`.
- Does not retry `401` or `404`.
- Retries `429` and `503`.
- Throws typed API errors with status and endpoint.
- Aborts requests after timeout and does not retry timeout aborts.

**Why:** Proves the client is read-only and safe before later services depend on it.

### `apps/api/src/integrations/repairshopr/repairshopr-rate-limiter.test.ts`

**Change:** Add deterministic limiter tests.

Cover:

- First 180 requests in a window do not wait.
- Request 181 waits until the oldest request leaves the 60 second window.
- Old timestamps are pruned when the clock advances.

**Why:** Locks the documented RepairShopr rate limit into executable behavior.
