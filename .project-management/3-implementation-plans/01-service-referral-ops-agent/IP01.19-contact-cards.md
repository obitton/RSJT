## Overview

Add manager-accessible contact cards for identified customer conversations. The contact card uses confirmed intake data already stored on the conversation: name, phone, email, and service address. A card is available only when the conversation has a customer name, phone number, and an intake state that indicates the customer has been identified enough to continue the workflow.

## Proposed Structure

- Add shared contact card DTOs for:
  - route params
  - contact data
  - availability response
  - vCard text response
- Add `ContactCardService` that reads conversation intake snapshots through an injected store and builds vCard 3.0 text.
- Add manager-only API routes:
  - `GET /manager/conversations/:conversationId/contact-card/preview`
  - `GET /manager/conversations/:conversationId/contact-card`
- Add mobile validation and format helpers under `apps/mobile/src/contact-cards/`.
- Add a manager route at `apps/mobile/src/app/(manager)/manager/contact-card/[conversationId].tsx`.
- Link the manager dashboard takeover rows to the contact card route.

The implementation stays local-only. It does not call RepairShopr write APIs and does not send any customer-facing communication.

## Availability Rules

A contact card is available when all rules pass:

- `customerName` is present.
- `phone` is present.
- `state` is one of `collecting`, `matched`, or `review_ready`.

Unavailable responses keep the preview endpoint useful by returning missing fields and state. The vCard endpoint returns `404` when the conversation is missing and `409` when the conversation exists but is not ready for a card.

## API Shape

### `GET /manager/conversations/:conversationId/contact-card/preview`

Requires `manager` role.

Returns JSON:

```json
{
  "available": true,
  "missingFields": [],
  "state": "review_ready",
  "contact": {
    "conversationId": "00000000-0000-4000-8000-000000060101",
    "fullName": "Casey Customer",
    "phone": "+15555550100",
    "email": "casey@example.com",
    "serviceAddress": "123 Main Street"
  }
}
```

Unavailable example:

```json
{
  "available": false,
  "missingFields": ["phone"],
  "state": "collecting",
  "contact": null
}
```

### `GET /manager/conversations/:conversationId/contact-card`

Requires `manager` role.

Returns `text/vcard; charset=utf-8`:

```text
BEGIN:VCARD
VERSION:3.0
FN:Casey Customer
TEL;TYPE=CELL:+15555550100
EMAIL:casey@example.com
ADR;TYPE=WORK:;;123 Main Street;;;;
NOTE:Service address: 123 Main Street
END:VCARD
```

## File-By-File Changes

### `packages/shared/src/domain/contact-cards.ts`

Add:

- `ContactCardParamsSchema`
- `ContactCardMissingFieldSchema`
- `ContactCardDataSchema`
- `ContactCardPreviewResponseSchema`
- `ContactCardVcardResponseSchema`
- exported TypeScript types for each schema

The contact card data includes `conversationId`, `fullName`, `phone`, `email`, and `serviceAddress`. `email` and `serviceAddress` are nullable. Missing fields are limited to `name`, `phone`, and `identified_state`.

### `packages/shared/src/domain/domain.test.ts`

Add tests for:

- available preview response with name, phone, email, and service address
- unavailable response with a missing phone
- vCard text response
- invalid contact data without name or phone

### `packages/shared/src/index.ts`

Export `./domain/contact-cards.js`.

### `apps/api/src/services/contact-card-service.ts`

Add:

- `ContactCardStore`
- `ContactCardServiceApi`
- `ContactCardService`
- `ContactCardNotFoundError`
- `ContactCardUnavailableError`

Responsibilities:

- Load `CustomerIntakeSnapshot` by conversation ID.
- Derive preview availability from the rules above.
- Generate vCard text from the same normalized contact data.
- Escape vCard text for backslashes, semicolons, commas, and newlines.
- Keep vCard generation deterministic for tests.

### `apps/api/src/routes/contact-card-routes.ts`

Add manager-only routes:

- `GET /manager/conversations/:conversationId/contact-card/preview`
- `GET /manager/conversations/:conversationId/contact-card`

The preview route returns JSON. The vCard route sets `Content-Type` to `text/vcard; charset=utf-8` and sends the generated text. Missing conversations map to `404`; unavailable cards map to `409`.

### `apps/api/src/app.ts`

Wire `ContactCardService` into `AppOptions`, default service creation, and route registration. The default service should reuse `IntakeRepository` so contact cards and manager intake previews read from the same conversation source.

### `apps/api/src/services/contact-card-service.test.ts`

Cover:

- preview is available with name and phone in a valid state
- preview lists missing fields for incomplete conversations
- blocked or unknown states are unavailable
- vCard includes optional email and service address when present
- missing conversation throws `ContactCardNotFoundError`
- unavailable vCard throws `ContactCardUnavailableError`

### `apps/api/src/tests/contact-card-routes.test.ts`

Cover:
